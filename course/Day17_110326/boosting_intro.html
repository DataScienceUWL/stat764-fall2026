Small trees, one after another

A forest grows hundreds of deep trees side by side and averages what they say. Boosting grows small trees one at a time, and fits each new tree to the mistakes the trees before it still make.

Boosting

A forest’s trees never see each other’s mistakes. Boosting’s trees see nothing else: each one is fitted to what the model so far still gets wrong. Can trees that fix each other’s mistakes beat trees that vote?

Boosting brings a new way to overfit, too many rounds, and the same old cure: choose on data the model was not fitted on.

1. Why does a forest let each split look at only a few random columns?

So the trees disagree. With every column available, the bagged trees all opened with prior stays and made the same mistakes, so averaging them cancelled little. Forcing variety at every split made their mistakes different: the forest reached 0.651 against bagging’s 0.630.

2. Why is the out-of-bag score honest when nothing was set aside?

Each bootstrap sample leaves out about a third of the stays, and each stay is scored only by the trees that left it out, trees that never saw it. It is the held-out rule from Meetings 3 and 6, paid for with the rows the bootstrap skips: 0.650, against 0.654 from grouped cross-validation and 0.651 on test.

3. The forest’s importance plot (impurity importance) ranks lab tests 2nd of 20 columns. Does that mean lab tests helps predict new patients? How would you check?

Not by itself: the two importances answer different questions. Impurity importance says how much the forest’s splits used a column on the training stays, and a count with many different values gets more chances to be picked, by luck as well as by signal. Whether a column helps with new patients is a question about patients the model did not see. Permutation importance asks it: shuffle one column on held-out patients and measure how much the AUC drops. Lab tests: 0.005. Discharge, ranked 4th by impurity: 0.063. Permutation has a blind spot of its own: when two columns carry the same information, shuffling one lets the other cover for it, as the studio’s near-copy showed. And neither number says what causes a readmission.

Part 1 · the idea, smallThirty made-up patients

Each patient has one column, a severity score recorded at admission, from 0 to 10, and one number to predict: days in the hospital. A tree that predicts a number works as in Meeting 15: each leaf predicts the average of its patients. Here every tree is a stump, a tree with a single question.

Step 1Start with the average

Before any tree, predict the same number for everyone: the average of the 30, days. What is still wrong for each patient is the residual, the actual days minus the prediction. The average squared residual is the training error, the MSE: .

Step 2Fit a small tree to what is still wrong

Grow a stump on the residuals, not on the days. It finds the one cut that best separates the patients the model under-predicts from those it over-predicts, and says one number for each side: the average residual there. Add a fraction of it to the model (the learning rate), compute the new residuals, and repeat. Each round, the right panel shows what is still wrong and the stump fitted to it; adding the stump moves the model on the left.

Step 3What the model is: one number and a list of stumps

The fitted model does not keep the 30 patients. It keeps a starting value, the average, and for each round one stump: its question and the two numbers it can say, the average residual on each side. To predict for a new patient, start at the average and add the learning rate times what each stump says for that patient. Earlier stumps never change: each round adds one more line to the list.

Step 4Keep going: when does it stop helping?

Every round lowers the training error, and nothing in the method ever stops it. After enough rounds the stumps are chasing single patients’ luck. To see when that starts, the page also makes up 200 new patients the same way and never fits on them. Their error is the honest one.

Step 5Two settings that act as one

Each learning rate has its own best round. A smaller rate takes smaller steps, so it needs more rounds to get to the same place, and the product of the two stays about the same:

The best round for each learning rate, on the 200 new patients
learning ratebest roundrate × round new-patient MSE thereafter 1,000 rounds

Two lessons follow. The learning rate and the number of rounds act as one setting: pick a small rate, then choose the rounds for it on data the model was not fitted on. And the number of rounds is a brake, not a capacity dial. A forest never gets worse with more trees, because it averages them; boosting does, because every round fits the training data a little more closely.

Step 6Why it is called gradient boosting

Write the loss for one patient as ½(y − F)², where F is the model’s current prediction. Its slope with respect to F is −(y − F). So the residual y − F is the negative gradient: for each patient, the direction that lowers the loss fastest. Each round fits a tree to that direction and takes a small step along it. It is gradient descent, one tree at a time.

Change the loss and the recipe still works. For a yes/no outcome, boosting builds up the log-odds and uses the log loss, whose negative gradient is y − p: the outcome (1 for came back, 0 for not) minus the predicted chance. That is what every tree in Part 2 is fitted to. So even when the task is classification, each tree is a regression tree: what it fits, y − p, is a number, not a yes or no.

One detail scikit-learn adds for yes/no outcomes

After a tree is grown on y − p, each leaf’s value is not the plain average of its residuals. It is one Newton step on the log loss: the sum of y − p in the leaf divided by the sum of p(1 − p). The idea is the same; the step is better sized.

Part 2 · the real dataThe same steps on the readmission data

Meeting 16’s training sample: 15,000 patients and their 21,352 stays. To choose the number of rounds, hold out a fifth of the patients, all of their stays together (3,000 patients, 4,263 stays, 517 of them readmitted), and fit on the rest (17,089 stays). Each tree asks up to three questions in a row (max_depth=3), for up to 1,000 rounds, at three learning rates. The score is the AUC.

18rounds at a learning rate of 0.3 (rate × round 5.4)
34rounds at 0.1 (rate × round 3.4)
112rounds at 0.03 (rate × round 3.4)
0.668the best held-out AUC, at 0.03; the other two 0.667

The same three patterns as the made-up patients. Training AUC climbs as long as the rounds continue, to 0.94 after 1,000 rounds at 0.3, while the held-out patients fall to 0.586: the trees are fitting single stays. The best rounds shrink as the rate grows, and for the two smaller rates the product is the same. And the three best scores are nearly equal, so the rate mostly changes how many rounds you need.

One caution about “best.” The held-out curve at 0.1 is nearly flat from round 20 to round 150 (0.659 to 0.667). Hold out a different fifth of the patients and the best round moves: in five other draws it was 25, 38, 65, 68 and 200 rounds, and the best held-out AUC itself ranged from 0.641 to 0.680, a bigger swing than the gap between any two of those rounds. The best round is a reasonable choice, not a precise one.

See it in Scikit-Learn

The model in Part 2, with every setting this page has been about. make_pipe is the notebook’s preprocessing (fill and scale the counts, one-hot the categories) with the model at the end.

from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import GroupShuffleSplit

# Hold out a fifth of the training PATIENTS (all their stays) to choose the rounds.
fit_i, val_i = next(GroupShuffleSplit(1, test_size=0.2, random_state=17)
                    .split(X_fit, y_fit, groups=groups_fit))

boost = make_pipe(GradientBoostingClassifier(
    n_estimators=1000,   # Step 4: the most rounds to try
    learning_rate=0.1,   # Step 5: how much of each tree to add
    max_depth=3,         # questions in a row per tree (Part 1's stumps: 1)
    random_state=0,
)).fit(X_fit.iloc[fit_i], y_fit[fit_i])

# staged_predict_proba: the predictions after round 1, 2, ..., 1000, from ONE fit.
Z_val = boost[:-1].transform(X_fit.iloc[val_i])     # the preprocessing alone
val_auc = [roc_auc_score(y_fit[val_i], p[:, 1])
           for p in boost["model"].staged_predict_proba(Z_val)]
best = int(np.argmax(val_auc)) + 1                    # 34

final = make_pipe(GradientBoostingClassifier(
    n_estimators=best, learning_rate=0.1, max_depth=3, random_state=0,
)).fit(X_fit, y_fit)
p_test = final.predict_proba(X_test)[:, 1]
print(roc_auc_score(y_test, p_test))                  # 0.647, scored once
print(type(final["model"].estimators_[0, 0]).__name__)  # DecisionTreeRegressor, even for yes/no

# What the model stores, and how one prediction adds up ("Inside one real prediction").
z = final["prep"].transform(X_test.iloc[[43]])        # the stay followed above, preprocessed
start = np.log(y_fit.mean() / (1 - y_fit.mean()))     # -2.03: the readmission rate as log-odds
steps = [0.1 * tree[0].predict(z)[0] for tree in final["model"].estimators_]   # 34 corrections
print(1 / (1 + np.exp(-(start + sum(steps)))))        # 0.311, what final.predict_proba gives

Boosting is older than the gradient version. The first method, AdaBoost (AdaBoostClassifier), was built for classification: instead of fitting residuals, each round reweights the cases the last learner got wrong, so the next one concentrates on them. It can boost any simple learner, though stumps are the usual choice. Gradient boosting replaced it in practice because one recipe covers any loss.

The tools the studio uses

  • staged_auc(model, rows, outcome) takes a fitted boosting pipeline and gives its AUC after round 1, 2, 3, … from one fit. The best round is np.argmax(...) + 1.
  • The held-out patients are X_fit.iloc[val_i] with y_fit[val_i]; fit on X_fit.iloc[fit_i] with y_fit[fit_i]. Both made in the notebook’s setup.
  • scores(probs) gives a model’s AUC, Brier score, average predicted chance and calibration slope on the test patients.
